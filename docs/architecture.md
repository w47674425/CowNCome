# 《赵云与阿斗》微信小游戏架构设计

> 基于 overview.md 玩法设计，面向「快速上线」的完整架构方案
> 版本：v1.0 · 2026-08-18

---

## 1. 关键前提：小游戏 ≠ 小程序

微信**小游戏**运行在 Canvas/WebGL 渲染管线，走 `game.js` 入口 + 游戏引擎，**不适用 WXML/WXSS 组件体系**。本架构按小游戏技术栈设计。

## 2. 技术选型

| 层 | 选型 | 理由 | 备选 |
|----|------|------|------|
| 客户端引擎 | **Cocos Creator 3.8+ (TypeScript)** | 微信小游戏生态最成熟；可视化编辑器 + 一键发布微信小游戏；项目已有 Cocos 分层约定（core/data/manager/game/ui） | Laya / 自研 canvas（不推荐，开发慢） |
| 后端 | **微信云开发 CloudBase** | 免运维、免域名、免备案；天然打通微信登录；云函数 + 云数据库 + 云存储一站式；个人开发者即可上线 | 自建 Node.js + 云服务器（需备案，慢） |
| 实时通信 | 云开发实时数据推送（第一阶段）/ 云托管 WebSocket（第二阶段 PvP） | 快速上线优先；真人 PvP 用增量推送 | 第三方 IM 服务 |
| 数据存储 | 云数据库（MongoDB 文档型） | 与云函数同生态，免索引配置 | MySQL（云开发支持但迁移成本高） |
| 广告 | 微信流量主广告组件（激励视频/插屏/Banner） | IAA 变现核心，官方组件 | 聚合 SDK（后期） |

**决策逻辑**：快速上线的核心约束是「免备案、免运维、链路短」。云开发把登录、存储、函数、广告全部收敛在微信生态内，一个环境跑通；Cocos 提供可视化编辑加速 UI/动画生产。两者是当前最快路径。

## 3. 前端分层结构（沿用项目既有约定）

```
assets/scripts/
├── core/                    # 入口 / 全局 / 常量 / 基类（不依赖业务）
│   ├── GameApp.ts           # 全局入口：生命周期、全局单例注册
│   ├── EventBus.ts          # 全局事件总线（模块解耦）
│   ├── Const.ts             # 常量：事件名/存储键/广告位 ID/场景名
│   └── Utils.ts             # 工具：随机/格式化/洗牌
├── data/                    # 数据模型 / 数值配置 / 规则引擎（纯逻辑，无渲染）
│   ├── models/              # 领域模型
│   │   ├── Unit.ts          # 兵种实例（类型/等级/攻击/攻速/格子坐标）
│   │   ├── Hero.ts          # 武将实例（字牌组合/技能/经验）
│   │   ├── PlayerState.ts   # 对局状态（馒头/格子/阿斗血量/退兵次数）
│   │   └── BattleState.ts   # 整局状态机（双方）
│   ├── config/              # 数值配置表（与 tuning 表同源）
│   │   ├── UnitConfig.ts    # 兵种数值：刀/枪/弓/骑 的攻击/攻速/射程/升级曲线
│   │   ├── HeroConfig.ts    # 武将数值：赵/关/张/黄/马 + 技能
│   │   ├── RecruitCost.ts   # 征兵成本递增曲线
│   │   ├── WaveConfig.ts    # 波次刷怪配置（PvE/AI）
│   │   ├── EquipConfig.ts   # 装备品质/碎片需求
│   │   └── AdConfig.ts      # 广告位 ID 与触发点
│   └── rules/               # 规则引擎（纯函数，可单测）
│       ├── SynthesizeRule.ts # 合成规则：同类同级 → 高一级
│       ├── CombatRule.ts     # 战斗结算：攻击/攻速/射程/穿透/减伤
│       ├── RecruitRule.ts    # 征兵：成本计算 + 掉落概率表
│       └── EconomyRule.ts    # 经济：击杀掉落/奖励结算
├── manager/                 # 单例管理器 / 平台 / 广告 / 网络
│   ├── PlatformManager.ts   # 平台适配层（微信/抖音双端抽象）
│   ├── NetworkManager.ts    # 云函数调用统一封装（loading/错误/重试）
│   ├── AdManager.ts         # 广告管理：激励视频/插屏/Banner 加载与回调
│   ├── AudioManager.ts      # 音频（文字打击音效）
│   ├── StorageManager.ts    # 本地缓存（登录态/设置/新手进度）
│   ├── MatchManager.ts      # 匹配流程（PvE 直开 / PvP 进队列）
│   ├── GameStateManager.ts  # 对局状态机（IDLE→MATCHING→BATTLE→SETTLE）
│   └── UIManager.ts         # 页面切换/弹窗队列
├── game/                    # 玩法组件（战斗场景内）
│   ├── battle/
│   │   ├── BattleScene.ts   # 战斗场景入口（组装棋盘/波次/UI）
│   │   ├── GridBoard.ts     # 棋盘：格子管理、拖拽放置、铲子扩格
│   │   ├── UnitView.ts      # 兵种表现：汉字 Label + 攻击动效（复用）
│   │   ├── HeroView.ts      # 武将表现：组合激活动画 + 技能特效
│   │   ├── EnemyWave.ts     # 敌方波次刷怪（配置驱动）
│   │   ├── RecruitPanel.ts  # 征兵面板：按钮/冷却/结果展示
│   │   ├── RetreatSkill.ts  # 退兵技能（每局 1 次）
│   │   └── AIPlayer.ts      # AI 对手（阶段一 PvE 用，行为树）
│   └── effects/             # 特效（合成闪光/攻击轨迹/掉血飘字）
├── ui/                      # 页面 / 通用控件
│   ├── pages/
│   │   ├── MainMenu.ts      # 主菜单：开始/图鉴/商店/设置
│   │   ├── MatchPage.ts     # 匹配页
│   │   ├── BattlePage.ts    # 战斗页（装配 BattleScene）
│   │   ├── ResultPage.ts    # 结算页（掉落/翻倍广告/分享）
│   │   ├── CollectionPage.ts# 图鉴页
│   │   ├── ShopPage.ts      # 商店（神秘商人，道具仅当天有效）
│   │   └── EquipPage.ts     # 装备页（碎片合成/穿戴）
│   └── widgets/             # 通用控件
│       ├── Toast.ts / Dialog.ts / Countdown.ts / DamageLabel.ts
└── main.ts                  # 引擎入口（Cocos 场景启动）
```

**分层铁律**：
- `data` 层**零引擎依赖**（不 import cc），规则引擎纯函数可单测 —— 数值改动不碰渲染
- `manager` 层只做编排，不写玩法逻辑
- `game` 层只做战斗表现与交互，不写数值决策
- 跨层通信只走 `EventBus`，禁止组件间直接引用

## 4. 后端设计（云开发 CloudBase）

### 4.1 云函数目录

```
cloudfunctions/
├── login/            # 登录：openid → 用户档案（建号/回归）
├── user/             # 用户数据：金币/体力/段位查询与增减（服务端权威）
├── match/            # PvP 匹配：进池/撮合/开局（阶段二启用）
├── battle/           # 战斗结算：验证对局结果 → 发装备/金币 → 写记录
├── recruit/          # 征兵：服务端随机出牌（防作弊，客户端只做表现）
├── shop/             # 神秘商人：当日商品轮换/购买（仅当天有效）
├── collection/       # 图鉴：点亮/奖励发放
├── equip/            # 装备：碎片入库/激活
├── rank/             # 排行榜：段位/分数（配合开放数据域）
└── ad-verify/        # 激励视频广告完成回调验证（防刷）
```

### 4.2 云数据库集合

| 集合 | 关键字段 | 说明 |
|------|---------|------|
| `users` | openid, coins, stamina, staminaTs, rank, elo | 玩家档案；体力用时间戳恢复，防改本地时间 |
| `battles` | openid, result, mode, equipDrops, coins, createdAt | 对局记录（审计 + 装备掉落追溯） |
| `match_pool` | openid, elo, status, joinedAt | 匹配队列（阶段二） |
| `equip_inventory` | openid, equipId, quality, count | 装备背包（碎片计数） |
| `collection` | openid, heroIds[] | 图鉴点亮状态 |
| `shop_rotation` | date, items[], price | 按天轮换的商品表（服务端生成） |
| `rank` | openid, elo, season | 排行榜（开放数据域只读） |

### 4.3 服务端权威原则（防作弊核心）

| 数据 | 权威端 | 原因 |
|------|--------|------|
| 征兵随机结果 | **服务端** | 防止本地改概率/刷英雄字牌 |
| 击杀掉落（馒头） | 客户端表现 + 服务端校验 | 局内闭环，结算时对账 |
| 装备掉落 | **服务端** | 防刷装备，掉落表只在云端 |
| 金币/体力/段位 | **服务端** | 纯服务端权威 |
| 广告奖励 | **ad-verify 验证回调** | 防模拟广告点击 |

## 5. 核心系统设计

### 5.1 对局状态机（GameStateManager）

```
IDLE → MATCHING → COUNTDOWN(3s) → BATTLE → SETTLEMENT → IDLE
                ↘ PvE：直开 BATTLE（AIPlayer）
```

- 状态迁移由 manager 统一驱动，页面监听状态变化刷新 UI
- 对局结束触发 `battle` 云函数结算，客户端展示结果并落广告点

### 5.2 即时循环实现（0-30s）

```
击杀敌兵 ──(CombatRule 结算 + 馒头掉落动画)──▶ 馒头↑
征兵 ──(RecruitRule: 成本递增 + 掉落表)──▶ 随机出牌（兵种/字牌/铲子）
拖拽合成 ──(SynthesizeRule: 同类同级检测)──▶ 升级反馈
自动攻击 ──(波次驱动, UnitView 攻击动效)──▶ 击杀 → 循环
```

- 棋盘：`GridBoard` 持有格子数组，拖拽命中检测 + 合成配对
- 兵种表现：`UnitView` 用 Label 渲染汉字，攻击时播放字形动效（文字即视觉的落地）
- 对象池复用 UnitView，避免频繁 instantiate 卡顿

### 5.3 PvP 分阶段策略

| 阶段 | 方案 | 成本 | 说明 |
|------|------|------|------|
| MVP | **PvE + AI 对手**（AIPlayer 行为树） | 低 | 先跑通核心循环，AI 模拟对方征兵/进攻节奏 |
| 阶段二 | **异步/快照对战**（云数据库对战快照 + 云函数判定） | 中 | 低成本真人对抗，契合小游戏轻量节奏 |
| 阶段三 | **实时 PvP**（云托管 WebSocket） | 高 | 需要容器运维，压测后再上 |

**关键决策**：MVP 不做实时 PvP。1V1 塔防的核心快感在"经营己方战场 + 对比敌方进度"，快照对战（每 5-10 秒同步一次对方战场状态）即可复现"比对手多撑一秒"的体验，成本是实时方案的 1/5。

### 5.4 经济系统落地

| 货币 | 权威端 | 局内/局外 | 实现要点 |
|------|--------|----------|---------|
| 馒头 | 客户端 + 结算对账 | 局内 | RecruitCost 递增曲线；击杀掉落由 CombatRule 计算 |
| 金币 | 服务端 | 局外 | battle 云函数结算发放；图鉴点亮奖励 |
| 装备碎片 | 服务端 | 局外 | battle 掉落表云端；equip 云函数激活 |
| 体力 | 服务端 | 局外 | 时间戳恢复；激励视频补充 |

### 5.5 IAA 广告植入（沿用 overview 的压力点策略）

| 触发点 | 广告类型 | 逻辑 |
|--------|---------|------|
| 局内阿斗濒危 | 激励视频 | 看广告生成盾牌救阿斗（1 次/局） |
| 局外体力不足 | 激励视频 | 看广告 +30 体力 |
| 结算页 | 激励视频 | 掉落翻倍 |
| 结算后 | 插屏 | 自然过渡，不打断结算 |
| 主菜单 | Banner（可选） | 长尾填充 |

**注意**：所有激励视频奖励必须走 `ad-verify` 云函数验证服务端回调，广告组件只做展示。

## 6. 关键数据流

### 登录流
```
game.js 启动 → GameApp.init → PlatformManager.login(wx.login)
  → 云函数 login(code) → 服务端 openid 查/建 users → 返回用户档案
  → StorageManager 缓存登录态 → UIManager 进主菜单
```

### 对局流（PvE）
```
主菜单点开始 → MatchManager → 云函数 user(扣体力) → BATTLE
  → BattleScene 初始化（棋盘6格/波次/征兵）
  → 征兵: 云函数 recruit → 服务端随机 → 返回字牌 → RecruitPanel 展示
  → 击杀/合成/退兵 客户端实时表现
  → 阿斗血量归零 → 云函数 battle(结算) → 装备/金币入库 → ResultPage
```

### 广告流
```
触发广告点 → AdManager.showRewarded(广告位)
  → 用户看完 → 微信广告回调(服务端) → ad-verify 验证 → 发奖
  → AdManager 回调客户端 → UI 刷新
```

## 8. 提审注意（小游戏专属）

1. **类目资质**：休闲小游戏类目，需软著（可加急）或版号豁免说明（休闲类 IAA 目前走软著即可提审）
2. **广告**：流量主需累计 UV ≥ 1000 后开通，MVP 先埋点后开
3. **用户协议/隐私政策**：涉及 openid/广告数据，需挂隐私协议
4. **分包策略**：主包 < 4MB（Cocos 小游戏首包限制 4MB，总包 20MB），武将/波次配置走远程拉取，不打包
5. **性能**：文字渲染用系统字体即可（不引字库文件，省包体），动效用 shader/节点动画

## 9. 风险清单

| 风险 | 等级 | 应对 |
|------|------|------|
| 征兵随机性过大，运气差体验断裂 | 高 | 服务端保底：连续 N 次未出字牌必出；掉落表可远程热更 |
| 金币 source 中后期枯竭（图鉴有限） | 中 | 上线前用云函数日志估算产出，预留赛季奖励 source |
| 快照 PvP 的公平性（装备差异） | 中 | 匹配池按 elo + 装备分加权 |
| 广告依赖（激励视频填充率） | 中 | 广告位分优先级，填充失败降级为"看一次倒计时" |
